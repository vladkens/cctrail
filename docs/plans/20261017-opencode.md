# OpenCode

Read OpenCode history as a fifth source, like pi and fx.

## Thoughts

- History lives in `$XDG_DATA_HOME/opencode` (`~/.local/share/opencode`): `opencode.db` (SQLite,
  WAL, open read-only) and older JSON under `storage/`. Three schema generations exist; the
  current one keeps assistant usage in `session_message` and fork boundaries in `session_v2`.
- Assistant messages carry provider, model, cost, tokens (input, output, reasoning, cache read and
  write), times and the working directory; subagents are child sessions (`parent_id`).
- Double counting to avoid: session totals next to message rows, leftover JSON duplicating database
  rows, forks copying messages with new ids.
- Needs `rusqlite` (bundled SQLite): a heavier dependency than the rest, to weigh against the build
  time rule in agents.md.
- Models from providers outside the price catalog fall back to OpenCode's own cost.

## Open questions

- Whether to support the legacy JSON layout at all.
- The dependency: `rusqlite` with bundled SQLite or the system library.
