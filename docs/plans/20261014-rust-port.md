# Rust port

Replace the Python cctrail 0.2.1 with a Rust binary that gives the same numbers on the full local
history, behind a smaller CLI. The Python source at tag `v0.2.1` is the spec for parsing and
accounting; `uvx cctrail==0.2.1` is the reference for `make compare`.

## CLI

```
cctrail [period] [--by project|group|dir]   stats per project (the default command)
cctrail here                                the current directory's project: today, yesterday,
                                            this week, last week, this month, all time
cctrail days|weeks|months [period] [--models]
cctrail update-pricing                      download models.dev prices to ~/.cache/cctrail

Shared: --since/--until YYYY-MM-DD, --provider claude|codex, --json, -h/--help, -V/--version
period: today yesterday this-week last-week this-month last-month all (default all)
```

- A period can't be combined with `--since`/`--until`; `--since` after `--until` is an error.
  Usage errors and failures exit with 2 and a one-line message on stderr.
- Dropped from 0.2.1: `--no-config` (use `--by dir`), `--show-unmapped` (`--by dir` lists every
  directory), `stats`/`usage`/`project` command names.
- Stats table as in 0.2.1: mapped projects, one `@unmapped` row, `total`; below it the hint
  `N unmapped dirs · run cctrail --by dir`, and the config path or, when missing, where to create
  it and the readme's setup link. `--help` shows the config path.
- New: when tokens fall on models the price catalog lacks, print below the table
  `Cost excludes <tokens> on unpriced models: <a, b, …> · run cctrail update-pricing`; JSON gets a
  top-level `unpriced_models` list.
- JSON keeps the 0.2.1 shapes (`groups`/`periods`/`total`, the same field names, `workdir` for
  directories), so `make compare` diffs it directly; `query` reflects the new flags.
- Tables use color only when stdout is a terminal and `NO_COLOR` is unset, and fit the terminal
  width (`COLUMNS`, else `ioctl(TIOCGWINSZ)` through `libc` on Unix; no limit when unknown) by
  truncating the first column with `…`.

## Parity details

Easy to get wrong when porting; each needs a unit test or a fixture.

- Files: every `*.jsonl` under the roots, sorted by path components (`PathBuf` order, as Python's
  `Path`). Claude reads `<root>/projects` if it exists, else `<root>`. Codex reads
  `archived_sessions` and `sessions` if either exists, else `<root>`; a rollout id seen twice keeps
  its first position and the later file's content.
- JSON integers: only non-negative integers count; floats, bools, negatives and strings are 0.
  Timestamps follow Python's `fromisoformat` (`Z` accepted, naive means UTC).
- Claude: session id is the file stem without `agent-`; a file under a `subagents` directory is an
  agent. Assistant lines merge per file by `(message.id, requestId)`, else by `requestId`/`uuid`,
  keeping the largest usage; `cache_creation` splits 5m/1h; `advisor_message` iterations add up;
  speed comes from `usage.speed` or `service_tier`. Agents link to their parent through
  `Agent`/`Task` tool calls, `toolUseResult.agentId` and `<agent>.meta.json` `toolUseId`; an agent
  whose log is missing becomes a session from the tool result's usage.
- Codex: see `cctrail/parser/codex.py` at `v0.2.1`: `token_count` totals and deltas, inherited
  ordinals before `subagent_history_start_ordinal`, fork replay stripped by usage signatures,
  `spawn_agent` calls matched to child rollouts, the assistant-activity record dropped when a token
  count with a timestamp follows it.
- Billing: failed events and zero usage never count; identities deduplicate across sessions, the
  larger usage (then a known speed) winning; a sidechain copy drops when the direct one exists.
- Time: every non-failed event is a 5-minute window; windows merge; `days` counts only stamps
  whose root has billable usage in that bucket; stats split simultaneous time between names in
  integer microseconds and round to whole seconds by largest remainder. Days are local (system time
  zone, `TZ` respected), weeks start on Monday.
- Sort: stats by time, then tokens (both descending), then name; models by tokens descending,
  then provider, model, fast. Sum costs in the same event order as Python so they match to 1e-9.
