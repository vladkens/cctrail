# Ledger

Keep the parsed history in cctrail's own database, so numbers survive when the logs are gone (Claude
Code deletes sessions older than 30 days by default), a new machine doesn't need the old logs, and a
run reads only what changed.

## Design

- Place: SQLite (rusqlite with its bundled SQLite) in `$XDG_DATA_HOME/cctrail/ledger.db`, else
  `~/.local/share/cctrail`, `%LOCALAPPDATA%\cctrail` on Windows. On by default;
  `CCTRAIL_NO_LEDGER=1` reads the logs alone (tests set it unless they test the ledger).
- Contents: per history file (fx: a session directory) its path, size, mtime, parser version and
  swear dictionary, and what reading it alone gives: its one session (id, main, directories,
  remote), its events (time, model, six token counts, speed, effort, the harness's cost, the
  summed, background, sidechain and failed flags, Claude's dedup identity, the prompt's swear
  counts, `directed`, hash and model) and, as JSON, the links the work across files needs (Claude's
  agent calls, fallbacks and meta tool id; Codex's rollout meta, agent calls and token count
  signatures; pi's header and entry keys; fx's parent, agent activity and per-model totals). Never
  text. Tables `files`, `sessions`, `events`, `strings` (models, efforts); paths under the home
  directory as `~/…`.
- The boundary: each parser is split into `find` (the files, with size and mtime), `read` (one
  file alone) and `combine` (the work across files: profile copies, Claude's agents and fallbacks,
  Codex's copies per root and profile, fork replay and agents, pi's lineage, fx's agents and usage
  spread over local days). The ledger keeps `read`'s results only; `combine` runs every time on all
  files, stored and read now, in the order a full parse finds them, so copies and forks count as
  in a full parse. Nothing that depends on the time zone (fx's spread) is stored.
- Each run: unchanged files come from the ledger; the others are read and replace their rows in
  one transaction, except a file that had events and reads to none, which keeps them. A gone
  file's rows stay and count, unless a file here has their session (a moved file); of several gone
  ones with one session, the last read.
- Safeguards: rows of a gone file are never deleted; before a `PARSER_VERSION` bump replaces rows,
  the database is copied to `ledger.db.bak-<old version>`, the last two kept; WAL; `export` reads
  the database only when the ledger is off.
- `cctrail export FILE` writes a consistent copy (`VACUUM INTO`). `cctrail import FILE` matches
  by path, else by harness and session id: an imported file is added, or replaces ours when our
  file is gone and was read before theirs; it never deletes.

- [x] The ledger: schema, load, refresh, store in one transaction
- [x] Safeguards: gone files kept, files reading to none keep their rows, a backup before a parser
