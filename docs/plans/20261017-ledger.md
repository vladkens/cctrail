# Ledger

Keep the parsed history in cctrail's own database, so numbers survive when the logs are gone (Claude
Code deletes sessions older than 30 days by default), a new machine doesn't need the old logs, and a
run reads only what changed. First step: `cctrail export FILE` and `cctrail import FILE`, to move
between machines and keep a backup.

## Export and import

- `cctrail export FILE` writes the final sessions the reports read (after fork handling, imported
  ones included) into a new SQLite file through a temporary file beside it: tables `sessions` (id,
  root, main, directories, remote), `events` (time, model, six token counts, speed, effort, Claude's
  dedup identity, the harness's cost, the summed, background, sidechain and failed flags, the
  prompt's swear counts, `directed`, hash and model) and `meta` (format version, cctrail version,
  export time). Never text; paths under the home directory as `~/…`.
- `cctrail import FILE` checks the format and copies the file into `$XDG_DATA_HOME/cctrail/`, named
  by its export time, so the same file imports once. Every run reads those files and adds their
  sessions the logs lack, merged by (harness, session id): the logs' copy wins, a newer import over
  an older one; an fx session whose tree is in the logs adds only its time, as fx spreads a tree's
  usage over its sessions. Final sessions are enough for that, so the parsers stay as they are.
- What the merge can't see: fx's usage keeps the split over days made in the exporting machine's
  time zone, and a pi or Codex fork whose ancestor is only imported counts as if the ancestor
  were gone.

## Later

- The ledger: the same tables in `$XDG_DATA_HOME/cctrail/ledger.db`, updated on each run so a run
  parses only new history and the sessions of gone files stay. A first version is on the local
  branch `feat/ledger-full`.
