# Ledger

Keep the parsed history in cctrail's own file, so numbers survive when the logs are gone (Claude
Code deletes sessions older than 30 days by default), a new machine doesn't need the old logs, and a
run parses only what changed.

## Thoughts

- Store what the numbers need, not the raw logs: per session its id, harness, directory, repository
  and parent link; every event the accounting reads, activity-only ones included (a prompt's time
  opens an activity window); per billed event its time, model, tokens, speed, effort, the harness's
  own cost and the flags pricing and activity use (summed, background, failed), plus the identities
  deduplication needs. No prompts, no code, no tool output. Expected to be a small share of the
  logs' size: measure.
- Place: `~/.local/share/cctrail/` (XDG data, not the cache: once the logs are deleted it is the
  only copy). This changes the scope rule in agents.md (cctrail writes only under `~/.cache`).
- Update: remember each log file's size and mtime; skip unchanged files, parse new and grown ones.
  A deleted log file keeps its sessions in the ledger.
- Speed: a repeated run parses only new history; measure against today's full read.
- Prices stay computed at read time: the ledger keeps tokens, so price fixes reach old data.
- Parser changes: re-parse a file when it still exists and the parser version changed; data whose
  file is gone stays as it was parsed.
- Moving machines: `cctrail export FILE` and `cctrail import FILE`, merged by session id without
  duplicates. Paths under the home directory are stored as `~/...`, so machines with different user
  names fold into the same projects.
- Use case: a public usage page built from `cctrail days --models --json`, with history that
  outlives the logs.

## Open questions

- File format (JSONL, compressed or not), one file or one per harness.
- Whether the ledger is on by default or opt-in.
- How to show that some numbers come from the ledger only (their logs are gone).
