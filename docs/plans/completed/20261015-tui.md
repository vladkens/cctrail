# TUI

`cctrail` should show the numbers lightly: open, look, drill into a project or a model, close. A
ratatui interface on the approved mockup: projects, models and a timeline, each with a drill-down,
over the history parsed once.

## Decisions

- `cctrail` with no arguments and a terminal on stdout opens the TUI; any argument, `--json` or a
  pipe keeps the text report.
- The history is parsed once behind a loading frame; switching period, provider, metric or view is
  in memory. Numbers come from the existing accounting (`stats_by`, `usage_by_period`, `pricing`):
  a period and provider show the same totals as the text report.
- Periods: today, this week, this month, the last 30 days, all. Provider: both, claude, codex
  (events filtered by provider, the folds computed on all of them).
- Views: 1 Projects (time, tokens, cost, sessions, share; `other` as in the text report) → the
  project's models, its metric per day and its paths; 2 Models (tokens, cost, share) → the
  projects using it; 3 Timeline (per day, per week for all) → the projects of that day.
- Keys as the mockup: ←→ period, ↑↓ select, enter open, esc back, m metric (time, tokens, cost:
  sort, shares and bars), p provider, / filter, ? help, q quit. Colors from the terminal's palette
  as in macmon.
- ratatui with only its crossterm backend (no default features).

## Result

`cctrail` on a terminal opens the interactive view; the text report and JSON are unchanged. The
totals equal the text report's for the same period and provider. On the full local history the
first frame waits for the usual parse (~4.5 s); a switch or drill-down then takes ~10 ms. The
module is ~870 lines with its tests.
